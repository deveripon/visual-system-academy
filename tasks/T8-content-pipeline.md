# T8 — Content pipeline + integration

**Goal:** turn the agent-authored plain-JS content into typed, validated TypeScript the
app imports — and make that conversion reproducible on any machine.

## OWNS

- `scripts/convert-content.mjs`, `scripts/validate-content.mjs`, `scripts/chaos-entry-map.mjs`
- `src/data/index.ts`, `src/data/generated/**`
- the `convert` / `validate` npm scripts (request the `package.json` edit via `_INBOX.md`
  if you are not the integrator)

## MUST READ

`docs/AGENT_PROTOCOL.md` → `docs/CONTRACTS.md` C1, C8, C9, C10 → `docs/DATA_MODEL.md`.

## Spec

**`scripts/convert-content.mjs`** — for each file in contract C8:

1. Read `content/src/<file>.js`.
2. Replace the leading `window.<NAME> =` with `const <NAME> =`; append
   `export default <NAME>;`. The body is valid TS as-is (ES2019 object/array literals).
3. Prepend `/* GENERATED by scripts/convert-content.mjs — DO NOT EDIT */` and
   `// source: content/src/<file>.js`.
4. Write `src/data/generated/<file>.ts`.
5. Support `--watch` for authoring sessions.
6. Apply `CHAOS_ENTRY_REMAP` (contract C10) when converting `data-chaos.js`, so authored
   `entryAfter` ids are normalised to real step ids.
7. Strip any dossier key that is not in the `NodeId` union (interrupted authoring runs
   have left placeholder keys such as `MOREMARKER1`).
8. Missing source files must **warn and skip**, not crash — content lands incrementally
   and the app must still build while chapters are in flight.

**`src/data/index.ts`**

```ts
export const ALL_STEPS: Step[];    // STEPS_A ++ STEPS_B1 ++ STEPS_B2 ++ STEPS_C ++ STEPS_C2
export const CHAOS: ChaosMap;
export const getComponents: () => Promise<ComponentMap>;   // lazy chunk, idle-prefetched
```

Dossier merge order: `COMPONENTS` → `COMPONENTS_B` → `COMPONENTS_C` (later wins).
Run `validateContent()` in dev only.

**`scripts/validate-content.mjs`** — runs standalone against `content/src/` (so content
agents on any machine can check their work without a build), exits non-zero with the
offending id:

- step ids unique across every file
- `node` / `from` ∈ `NodeId`; every `related` id ∈ `NodeId`
- chapters 1–24 and non-decreasing across the concatenated array
- all ten `explain` keys present and non-empty
- `quiz.answer` within `options` range; branch steps carry no `when`
- every chaos `entryAfter` (post-remap) resolves to a real step id
- a dossier exists for all 87 `NodeId`s (warn-list the missing ones rather than throwing
  while content is still landing)
- `effects` values ∈ `EffectId`; packet `layers` ∈ `PacketLayer`

## ACCEPTANCE

- `pnpm convert` regenerates everything from `content/src/` deterministically.
- `pnpm validate` reports a clean bill (or a precise, actionable list).
- `pnpm build` succeeds with the generated files in place.
- `src/data/generated/**` is git-ignored and never hand-edited.
- Deleting `src/data/generated/` and running `pnpm dev` restores a working app.

## VERIFY

```bash
rm -rf src/data/generated && pnpm convert && pnpm validate && pnpm typecheck && pnpm build
```
